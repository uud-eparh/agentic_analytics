### 📌 О проекте

**Agentic Analytics** — это полноценный дата-контур для автоматического скоринга проблемных клиентов в E-commerce. Проект демонстрирует интеграцию современных инструментов: от сбора и трансформации данных до работы с LLM и BI-визуализации.

**Ключевая идея:** LLM-агент анализирует транзакции интернет-магазина, выявляет проблемных клиентов, классифицирует их по статусам («Красный», «Желтый», «Зеленый») и выдает рекомендации для службы поддержки. Все результаты визуализированы в дашборде.

### 🧠 LLM-агент

#### Как работает

1. **Извлечение данных:** Агент запрашивает из ClickHouse всех клиентов с проблемными транзакциями (`failed`, `refund`, `chargeback`).
2. **Формирование промпта:** Для каждого клиента передаются:
   - Количество неудачных попыток
   - Сумма потерь
   - Тексты жалоб (если есть)
3. **Обработка LLM:** Mistral 7B анализирует данные и классифицирует клиента по правилам:
   - **«Красный»** — потеря > 5000$ → срочный контакт с бонусом 10%
   - **«Желтый»** — > 3 жалоб → проверка логов платежного шлюза
   - **«Зеленый»** — остальные → стандартная анкета
4. **Сохранение:** Результаты записываются в витрину `client_scoring`.
5. **Визуализация:** Данные отображаются в Superset.

#### Пример промпта

```
Ты — Senior Support-аналитик в крупном E-commerce.
Твоя задача: на основе сырых данных из БД (жалобы и суммы) принять РЕШЕНИЕ.

Правила:
1. Если сумма потерь > 5000$ -> статус "Красный". 
   Действие: "Связаться с клиентом в течение 1 часа и предложить бонус 10%".
2. Если жалоб больше 3 от одного юзера -> статус "Желтый". 
   Действие: "Проверить логи оплаты, возможно сбой платежного шлюза".
3. Во всех остальных случаях -> статус "Зеленый". 
   Действие: "Отправить стандартную анкету удовлетворенности".

Ты ОБЯЗАН вернуть ТОЛЬКО JSON.
Формат: {"user_id": 123, "status": "Красный", "action": "текст действия", "reason": "краткая причина"}
Никаких лишних слов, только JSON.
```

### 🛠️ Установка и запуск

#### 1. Клонирование и подготовка

```bash
git clone <your-repo>
cd agentic_analytics

# Создание виртуального окружения
python3.11 -m venv .venv
source .venv/Scripts/activate  # Windows
# source .venv/bin/activate    # Linux/Mac

# Установка зависимостей
pip install -r requirements.txt
```

#### 2. Запуск инфраструктуры

```bash
# Поднятие ClickHouse и Superset
docker-compose up -d

# Проверка работы ClickHouse
docker exec -it agentic_clickhouse clickhouse-client --user=admin --password=admin --query="SHOW TABLES FROM analytics"
```

#### 3. Загрузка данных

```bash
# Скачивание датасета с Kaggle
kaggle datasets download carrie1/ecommerce-data -p data/
cd data && unzip ecommerce-data.zip && cd ..

# Загрузка в ClickHouse
python scripts/load_data.py
```

#### 4. Запуск LLM-агента

```bash
# Убедитесь, что Ollama запущен
ollama serve

# Запуск анализа
python scripts/analyze_all.py
```

#### 5. Доступ к дашборду

```
Superset: http://localhost:8088
Login: admin / Password: admin
```

### 🧪 Что демонстрирует проект

1. **Интеграция LLM в бизнес-процессы** — агент не просто «болтает», а принимает решения на основе данных.
2. **Полный дата-контур** — от сырых данных до BI-визуализации.
3. **Работа с большими данными** — ClickHouse обрабатывает 406k транзакций, витрина строится на 3.7k клиентов.
4. **CI/CD-подход** — всё запускается через Docker Compose одной командой.
5. **Промпт-инжиниринг** — строгий JSON-формат, четкие правила, бизнес-ориентированный вывод.
6. **Локальный LLM** — модель запускается локально (Ollama), без необходимости платить за API.
